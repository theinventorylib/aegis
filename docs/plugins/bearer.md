# Bearer Plugin

The Bearer plugin provides explicit support for Bearer token authentication in Aegis. 

> [!NOTE]
> The core `AuthMiddleware` already supports Bearer tokens from `Authorization` headers. This plugin serves as a **marker plugin** to explicitly indicate that Bearer authentication is enabled in your application and provides documentation for this feature.

## Overview

When the bearer plugin is registered, it signals that your Aegis application accepts Bearer tokens for authentication. The actual Bearer token extraction and validation is handled by the core `AuthMiddleware`, which checks for tokens in the following order:

1. Session cookie (`aegis_session`)
2. `Authorization: Bearer <token>` header

This means **all protected routes** (core and plugin routes) automatically support both authentication methods without any additional configuration.

## Installation

```bash
go get github.com/theinventorylib/aegis/plugins/bearer
```

## Usage

### Basic Setup

```go
import (
    "github.com/theinventorylib/aegis"
    "github.com/theinventorylib/aegis/plugins/bearer"
    "github.com/theinventorylib/aegis/plugins/jwt"
)

// Create Aegis instance
auth, err := aegis.New(
    config.WithDB(dbProvider),
    config.WithRouter(router),
)
if err != nil {
    log.Fatal(err)
}

// Register JWT plugin for token generation
jwtPlugin := jwt.New(&jwt.Config{
    DB: dbProvider,
})
auth.Use(context.Background(), jwtPlugin)

// Register bearer plugin to indicate Bearer auth is enabled
bearerPlugin := bearer.New(&bearer.Config{})
auth.Use(context.Background(), bearerPlugin)

// Mount routes
auth.MountRoutes("/auth")
```

### Making Authenticated Requests

Once the bearer plugin is registered, clients can authenticate using Bearer tokens:

```bash
# Get a JWT token
curl -X POST http://localhost:8080/auth/jwt/token \
  -H "Content-Type: application/json" \
  -H "Cookie: aegis_session=<session_token>"

# Use the token with Bearer authentication
curl -X GET http://localhost:8080/auth/protected \
  -H "Authorization: Bearer <access_token>"
```

## How It Works

### Authentication Flow

1. **Client sends request** with `Authorization: Bearer <token>` header
2. **Core AuthMiddleware** extracts the token
3. **SessionService** validates the token (could be a session token or JWT)
4. **User context** is injected into the request
5. **Protected route** receives authenticated request

### Token Types

The Bearer plugin works with any token type that the `SessionService` can validate:

- **Session tokens**: Generated by core session management
- **JWT access tokens**: Generated by the JWT plugin
- **Custom tokens**: Any token format supported by your SessionService

## Integration with JWT Plugin

The bearer plugin works seamlessly with the JWT plugin:

```go
// Register both plugins
auth.Use(ctx, jwtPlugin)
auth.Use(ctx, bearerPlugin)

// Clients can now use JWT tokens as Bearer tokens
// Authorization: Bearer <jwt_access_token>
```

## Security Considerations

> [!WARNING]
> **HTTPS Required**: Always use HTTPS in production when using Bearer tokens. Bearer tokens in HTTP headers are vulnerable to interception.

> [!IMPORTANT]
> **Token Storage**: Advise clients to store Bearer tokens securely (e.g., in secure storage, not localStorage for web apps).

### Best Practices

1. **Use short-lived tokens**: Configure JWT plugin with short access token expiry
2. **Implement token refresh**: Use refresh tokens to obtain new access tokens
3. **Validate token scope**: Implement additional authorization checks beyond authentication
4. **Monitor token usage**: Log and monitor Bearer token authentication attempts

## Troubleshooting

### Bearer token not working

**Problem**: Requests with `Authorization: Bearer <token>` header return 401 Unauthorized.

**Solutions**:
1. Verify the token is valid (not expired, properly signed)
2. Check that the token exists in the session table (for session tokens) or is a valid JWT
3. Ensure the `Authorization` header format is exactly `Bearer <token>` (note the space)
4. Verify the bearer plugin is registered before mounting routes

### Token validation fails

**Problem**: Valid-looking tokens are rejected.

**Solutions**:
1. Check SessionService configuration
2. For JWT tokens, verify JWT plugin is registered and keys are properly initialized
3. Enable debug logging to see validation errors
