## Database Migrations

Aegis does not use "auto-migration" magic. Instead, it provides a powerful CLI tool to export the SQL schemas required for the core and various plugins. This gives you full control over your database schema and versioning.

## Using the CLI

The Aegis CLI allows you to export migrations in formats compatible with popular Go migration tools.

### Supported Formats

- `sql`: Raw SQL files.
- `goose`: Migrations compatible with [Goose](https://github.com/pressly/goose).
- `golang-migrate`: Migrations compatible with [golang-migrate](https://github.com/golang-migrate/migrate).

### Supported Databases

- `postgresql`
- `mysql`
- `sqlite`

## Exporting Migrations

To export migrations for the core Aegis tables and specific plugins, use the `migrate export` command.

```bash [Terminal]
# Export migrations for Core + Email OTP + OAuth in PostgreSQL format
aegis migrate export \
  --driver postgres \
  --format golang-migrate \
  --plugins emailotp,oauth \
  --out ./migrations
```

### Command Options

| Option | Description |
| --- | --- |
| `--driver` | The database driver (`postgres`, `mysql`, `sqlite`) |
| `--format` | The migration format (`sql`, `goose`, `golang-migrate`) |
| `--plugins` | Comma-separated list of plugins to include |
| `--out` | Output directory for the migration files |

## Managing Schema Changes

Aegis handles schema evolution by providing updated migration files in each release. When upgrading Aegis, you should re-run the export command and apply the new migration files using your preferred migration tool.
