# SQLite Setup

SQLite is a lightweight, file-based database perfect for development, testing, and small to medium applications. It requires no separate server process and stores the entire database in a single file.

## Quick Start

```go
import (
    "database/sql"
    _ "github.com/mattn/go-sqlite3"
    
    "github.com/theinventorylib/aegis"
    "github.com/theinventorylib/aegis/config"
)

func main() {
    // Connect to SQLite (creates file if doesn't exist)
    db, err := sql.Open("sqlite3", "./aegis.db")
    if err != nil {
        log.Fatal(err)
    }
    defer db.Close()
    
    // Verify connection
    if err := db.Ping(); err != nil {
        log.Fatal(err)
    }
    
    // Initialize Aegis
    cfg := config.Default().
        WithDB(db).
        WithRouter(router).
        WithSecret([]byte("your-secret-key"))
    
    auth := aegis.New(context.Background(), cfg)
}
```

## Drivers

### mattn/go-sqlite3 (CGO Required)

Most popular and feature-complete driver:

```bash
go get github.com/mattn/go-sqlite3
```

```go
import _ "github.com/mattn/go-sqlite3"

db, err := sql.Open("sqlite3", "./aegis.db")
```

**Pros:**
- ✅ Full SQLite feature support
- ✅ Battle-tested and stable
- ✅ Excellent performance

**Cons:**
- ❌ Requires CGO (C compiler needed)
- ❌ Cross-compilation is complex

### modernc.org/sqlite (Pure Go)

CGO-free alternative:

```bash
go get modernc.org/sqlite
```

```go
import _ "modernc.org/sqlite"

db, err := sql.Open("sqlite", "./aegis.db")
```

**Pros:**
- ✅ No CGO required
- ✅ Easy cross-compilation
- ✅ Works in all Go environments

**Cons:**
- ⚠️ Slightly slower than CGO version
- ⚠️ Less community adoption

::callout{icon="i-heroicons-information-circle" color="blue"}
For production SQLite usage, prefer `mattn/go-sqlite3` for best performance. Use `modernc.org/sqlite` when CGO is not available or for easier deployment.
::

## Connection Options

### File-based Database

```go
// Relative path
db, err := sql.Open("sqlite3", "./data/aegis.db")

// Absolute path
db, err := sql.Open("sqlite3", "/var/lib/aegis/aegis.db")

// Automatic directory creation
os.MkdirAll("./data", 0755)
db, err := sql.Open("sqlite3", "./data/aegis.db")
```

### In-Memory Database

Perfect for testing:

```go
// Private in-memory database (ephemeral)
db, err := sql.Open("sqlite3", ":memory:")

// Shared in-memory database (accessible across connections)
db, err := sql.Open("sqlite3", "file::memory:?cache=shared")
```

### Connection Parameters

```go
// With pragmas for performance
dsn := "./aegis.db?" +
       "_journal_mode=WAL&" +      // Write-Ahead Logging
       "_busy_timeout=5000&" +     // Wait 5s on locked database
       "_synchronous=NORMAL&" +    // Balance safety/performance
       "_cache_size=1000&" +       // Cache pages
       "_foreign_keys=true"        // Enable foreign key constraints

db, err := sql.Open("sqlite3", dsn)
```

## Performance Optimization

### Write-Ahead Logging (WAL)

Dramatically improves concurrent access:

```go
// Enable WAL mode
db.Exec("PRAGMA journal_mode=WAL;")

// Or in DSN
dsn := "./aegis.db?_journal_mode=WAL"
```

**Benefits:**
- ✅ Readers don't block writers
- ✅ Writers don't block readers
- ✅ Better performance for most workloads
- ✅ Crash-safe

### Recommended PRAGMAs

```go
db, err := sql.Open("sqlite3", "./aegis.db")

// Performance settings
db.Exec("PRAGMA journal_mode=WAL;")
db.Exec("PRAGMA synchronous=NORMAL;")
db.Exec("PRAGMA cache_size=1000;")
db.Exec("PRAGMA temp_store=MEMORY;")
db.Exec("PRAGMA mmap_size=30000000000;")

// Enable foreign keys
db.Exec("PRAGMA foreign_keys=ON;")
```

### Connection Pool Settings

SQLite works best with limited concurrency:

```go
db, err := sql.Open("sqlite3", "./aegis.db?_journal_mode=WAL")

// SQLite-specific pool settings
db.SetMaxOpenConns(1)  // Serialize writes (recommended)
// OR
db.SetMaxOpenConns(10) // Allow concurrent reads (WAL mode only)

db.SetMaxIdleConns(1)
db.SetConnMaxLifetime(0) // No limit
```

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
**Important**: SQLite handles one writer at a time. Set `MaxOpenConns(1)` to serialize access, or use WAL mode with `MaxOpenConns > 1` to allow concurrent reads.
::

## Schema Migration

### 1. Generate SQL Schema

```bash
# Install CLI
go install github.com/theinventorylib/aegis/cmd/aegis@latest

# Export SQLite schema
aegis migrate export --driver sqlite --out ./migrations
```

### 2. Apply Migrations

#### Using golang-migrate

```bash
migrate -path ./migrations -database "sqlite3://./aegis.db" up
```

#### Using goose

```bash
goose -dir ./migrations sqlite3 ./aegis.db up
```

#### Using sqlite3 CLI

```bash
sqlite3 aegis.db < migrations/001_create_users.sql
sqlite3 aegis.db < migrations/002_create_accounts.sql
sqlite3 aegis.db < migrations/003_create_sessions.sql
sqlite3 aegis.db < migrations/004_create_verification_requests.sql
```

## Core Schema

### Users Table

```sql
CREATE TABLE users (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE NOT NULL,
    email_verified INTEGER DEFAULT 0,  -- SQLite doesn't have BOOLEAN
    phone TEXT,
    phone_verified INTEGER DEFAULT 0,
    metadata TEXT,  -- JSON stored as TEXT
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_phone ON users(phone);
```

### Sessions Table

```sql
CREATE TABLE sessions (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    session_token TEXT UNIQUE NOT NULL,
    refresh_token TEXT UNIQUE NOT NULL,
    ip_address TEXT,
    user_agent TEXT,
    expires_at TEXT NOT NULL,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX idx_sessions_user_id ON sessions(user_id);
CREATE INDEX idx_sessions_token ON sessions(session_token);
CREATE INDEX idx_sessions_expires ON sessions(expires_at);
```

### Accounts Table

```sql
CREATE TABLE accounts (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    account_type TEXT NOT NULL,
    provider TEXT,
    provider_account_id TEXT,
    password_hash TEXT,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT DEFAULT CURRENT_TIMESTAMP,
    
    UNIQUE(provider, provider_account_id),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE INDEX idx_accounts_user_id ON accounts(user_id);
CREATE INDEX idx_accounts_provider ON accounts(provider, provider_account_id);
```

## SQLite Limitations

### Data Types

SQLite has only 5 storage classes:

| SQL Type | SQLite Storage | Notes |
|----------|----------------|-------|
| `TEXT` | TEXT | Strings, JSON |
| `INTEGER` | INTEGER | Booleans (0/1), timestamps |
| `REAL` | REAL | Floating point |
| `BLOB` | BLOB | Binary data |
| `NULL` | NULL | - |

### Boolean Handling

```sql
-- SQLite doesn't have native BOOLEAN type
-- Use INTEGER with 0 (false) and 1 (true)

CREATE TABLE users (
    email_verified INTEGER DEFAULT 0  -- 0 = false, 1 = true
);

-- In Go, database/sql handles conversion automatically
var emailVerified bool
db.QueryRow("SELECT email_verified FROM users WHERE id = ?", id).Scan(&emailVerified)
```

### Concurrency

- **One writer at a time** - Writes are serialized
- **Multiple readers** - With WAL mode only
- **Busy timeout** - Connections wait for locks
- **Not suitable for high write throughput**

### Size Limits

- **Maximum database size**: 281 TB (theoretical)
- **Practical limit**: Few hundred GB
- **Maximum row size**: ~1 GB
- **Recommended size**: < 100 GB

## When to Use SQLite

### ✅ Good For

- **Development and testing**
- **Small to medium applications** (< 100K users)
- **Single-server deployments**
- **Embedded systems**
- **Low to moderate write traffic**
- **Read-heavy workloads**
- **Edge computing**
- **Desktop applications**

### ❌ Not Recommended For

- **High write concurrency** (> 100 writes/sec)
- **Multi-server deployments** (no network protocol)
- **Very large datasets** (> 100 GB)
- **Complex transactions** across network
- **When you need stored procedures**

## Deployment

### File Permissions

```bash
# Create data directory
mkdir -p /var/lib/aegis

# Set permissions
chmod 755 /var/lib/aegis

# Database file should be writable by application
chmod 644 /var/lib/aegis/aegis.db

# WAL and SHM files are created automatically
```

### Systemd Service

```ini
[Unit]
Description=Aegis Application
After=network.target

[Service]
Type=simple
User=aegis
Group=aegis
WorkingDirectory=/var/lib/aegis
ExecStart=/usr/local/bin/aegis-app
Environment="DATABASE_PATH=/var/lib/aegis/aegis.db"

[Install]
WantedBy=multi-user.target
```

### Docker

```dockerfile
FROM golang:1.21-alpine AS builder

# Install build dependencies for mattn/go-sqlite3
RUN apk add --no-cache gcc musl-dev

WORKDIR /app
COPY . .
RUN go build -o aegis-app .

FROM alpine:latest
RUN apk add --no-cache ca-certificates

COPY --from=builder /app/aegis-app /usr/local/bin/
RUN mkdir -p /data

ENV DATABASE_PATH=/data/aegis.db
VOLUME ["/data"]

CMD ["aegis-app"]
```

## Backup and Restore

### Online Backup (Safe)

```go
import "github.com/mattn/go-sqlite3"

func backupDatabase(src, dst string) error {
    srcDB, err := sql.Open("sqlite3", src)
    if err != nil {
        return err
    }
    defer srcDB.Close()
    
    dstDB, err := sql.Open("sqlite3", dst)
    if err != nil {
        return err
    }
    defer dstDB.Close()
    
    // Use SQLite backup API
    // (requires direct use of mattn/go-sqlite3 API)
    return nil
}
```

### File Copy (Offline)

```bash
# Stop application first
systemctl stop aegis-app

# Copy all WAL files
cp aegis.db aegis.db.backup
cp aegis.db-wal aegis.db.backup-wal
cp aegis.db-shm aegis.db.backup-shm

# Or use sqlite3 CLI for clean backup
sqlite3 aegis.db ".backup aegis.db.backup"
```

### Automated Backups

```bash
#!/bin/bash
# backup-aegis.sh

DB_PATH="/var/lib/aegis/aegis.db"
BACKUP_DIR="/backups/aegis"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)

mkdir -p "$BACKUP_DIR"
sqlite3 "$DB_PATH" ".backup '$BACKUP_DIR/aegis_$TIMESTAMP.db'"

# Keep only last 7 days
find "$BACKUP_DIR" -name "aegis_*.db" -mtime +7 -delete
```

## Troubleshooting

### "database is locked"

- Enable WAL mode: `PRAGMA journal_mode=WAL;`
- Increase busy timeout: `_busy_timeout=5000`
- Reduce `MaxOpenConns` to 1
- Check for long-running transactions

### "UNIQUE constraint failed"

- Check for duplicate emails or session tokens
- Verify your insert logic handles conflicts
- Use `INSERT OR REPLACE` if appropriate

### "unable to open database file"

- Check file permissions
- Verify directory exists and is writable
- Ensure path is correct (relative vs absolute)

### Poor write performance

- Enable WAL mode
- Batch inserts in transactions
- Increase `cache_size` pragma
- Consider switching to PostgreSQL/MySQL

### Database file corruption

- Always use `PRAGMA synchronous=FULL` for critical data
- Enable WAL mode for crash safety
- Regular backups
- Don't kill process during writes

## Best Practices

1. **Enable WAL mode** - Better concurrency and safety
2. **Use foreign key constraints** - `PRAGMA foreign_keys=ON;`
3. **Batch writes in transactions** - Much faster
4. **Set busy timeout** - Prevent lock errors
5. **Regular backups** - SQLite files can corrupt
6. **Use prepared statements** - sqlc does this automatically
7. **Monitor database size** - Plan migration to PostgreSQL if growing large
8. **Test with realistic data** - SQLite behaves differently at scale

## Migration to PostgreSQL/MySQL

When your application outgrows SQLite:

```bash
# Export data from SQLite
aegis migrate export --driver sqlite --out ./from-sqlite

# Import to PostgreSQL
psql -d aegis_prod < from-sqlite/001_create_users.sql

# Or use migration tool
pgloader sqlite://./aegis.db postgres://localhost/aegis_prod
```
