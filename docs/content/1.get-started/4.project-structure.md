## Aegis Structure

Aegis is organized into a core library and several official plugins. This modular design keeps the core lightweight while allowing for powerful extensions.

```bash
aegis/
├── auth/                # Core authentication logic and models
├── core/                # Core shared utilities, interfaces, and middleware
├── config/              # Config options
├── plugins/             # Official plugins (Email, SMS, OAuth, etc.)
│   ├── emailotp/
│   ├── sms/
│   ├── oauth/
│   └── ...
├── cmd/                 # CLI tools
│   └── aegis/           # Main Aegis CLI entry point
├── router/              # Router-specific implementations (e.g., Chi)
└── exporter/            # Migration export logic
```

### `auth/`

Contains the core authentication implementation, including database models, schema definitions, and the default store implementation.

### `core/`

Houses the fundamental building blocks of Aegis:
- **Interfaces**: Define how plugins and stores interact.
- **Middleware**: Built-in HTTP middleware for session handling and CSRF protection.
- **Config**: Global configuration options.
- **Utils**: Shared helper functions.

### `config/`
Contains Methods and Default Config options used throughout Aegis

### `plugins/`

Each folder in `plugins/` is a self-contained module that adds specific functionality. Plugins can have their own:
- **Models**: Database entities specific to the plugin.
- **Migrations**: SQL scripts for the plugin's schema.
- **Handlers**: HTTP endpoints provided by the plugin.
- **Store**: Database interaction logic for the plugin.

### `cmd/aegis/`

The source code for the Aegis CLI. Use this tool to manage migrations and scaffolding.

### `router/`

Aegis aims to be router-agnostic but provides official implementations for popular routers like `chi`.

### `exporter/`
Core setup for migrations and schema exports
