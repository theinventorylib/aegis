## Architecture Overview

Aegis is built on a **layered architecture** that separates concerns and provides flexibility:

### Core Layer
The core provides the essential building blocks:
- **User Management**: Create, update, and manage user accounts
- **Session Management**: Secure token-based sessions with refresh tokens
- **Password Authentication**: Built-in Argon2id hashing
- **CSRF Protection**: Automatic CSRF token generation and validation
- **Middleware**: HTTP middleware for session validation and authentication

### Plugin Layer
Plugins extend the core with additional functionality:
- **Self-contained**: Each plugin manages its own schema, models, and handlers
- **Optional**: Only include what you need
- **Composable**: Plugins can work together seamlessly

### Store Layer
The store layer handles database interactions:
- **Interface-based**: Define your own store implementations
- **Default Implementations**: Provided for PostgreSQL, MySQL, and SQLite
- **Type-safe**: Generated with sqlc for compile-time safety

## Key Concepts

### Sessions

Aegis uses a dual-token approach for session management:

- **Access Token**: Short-lived token for API requests
- **Refresh Token**: Long-lived token for obtaining new access tokens

Sessions can be stored in:
- **Database**: Default persistence layer
- **Redis**: Optional caching for high-performance scenarios

### CSRF Protection

For web applications, Aegis provides automatic CSRF protection:

```go
// Enable CSRF middleware
router.Use(auth.CSRFMiddleware())

// CSRF tokens are automatically validated on state-changing requests
```

### Database Agnostic

Aegis works with multiple databases through a unified interface:

```go
// PostgreSQL
db, _ := sql.Open("pgx", dsn)

// MySQL
db, _ := sql.Open("mysql", dsn)

// SQLite
db, _ := sql.Open("sqlite3", dsn)

// Use the same Aegis API regardless of database
auth := aegis.New(&core.Config{DB: db})
```

### Type Safety

Aegis uses **sqlc** to generate type-safe database code:
- No runtime reflection
- Compile-time query validation
- Strong typing for all database operations

## Schema Design

### Minimal Core Schema

Aegis requires only 4 tables in the core:

| Table | Purpose |
| --- | --- |
| `users` | User accounts and basic information |
| `sessions` | Active user sessions and tokens |
| `verification_requests` | Email/phone verification tracking |
| `password_reset_tokens` | Password reset flow management |

### Plugin Schemas

Each plugin can define its own tables:

- **Email OTP**: Stores email verification codes
- **Organizations**: Teams, members, and roles
- **JWT**: Token blacklists and rotation tracking
- **Admin**: Audit logs and admin-specific data

## Migration Strategy

Aegis provides a CLI to export migrations:

```bash
# Export core + specific plugins
aegis migrate export \
  --driver postgres \
  --format golang-migrate \
  --plugins emailotp,oauth,organizations \
  --out ./migrations
```

This approach gives you:
- **Version Control**: Track schema changes in your repository
- **Review Process**: Review migrations before applying
- **Flexibility**: Use any migration tool you prefer
