# Session Management

Aegis uses a robust **dual-token architecture** for session management, designed to balance security with user experience.

## Architecture

Every authenticated session consists of two tokens:

1.  **Access Token (Session Token)**
    *   **Purpose**: Used to authenticate requests.
    *   **Storage**: HTTP-only, Secure cookie.
    *   **Lifetime**: Short (default: 24 hours).
    *   **Validation**: Checked against database (or Redis) on every request.

2.  **Refresh Token**
    *   **Purpose**: Used to obtain new access tokens when the session expires.
    *   **Storage**: Database only (linked to the session).
    *   **Lifetime**: Long (default: 7 days).
    *   **Design**: Enables "Remember Me" functionality securely.

## Cookie Security

Aegis handles cookie management automatically with industry best practices:

*   **HttpOnly**: `true` (Prevents XSS attacks accessing the token)
*   **Secure**: `true` (HTTPS only, required in production)
*   **SameSite**: `Lax` (Prevents CSRF while allowing top-level navigation)
*   **Path**: `/`

You can customize these settings in the Aegis configuration:

```go
auth := aegis.New(ctx, &config.Config{
    Session: &config.SessionConfig{
        CookieSettings: config.CookieSettings{
            Name:     "myapp_session",
            SameSite: "Strict",
            Secure:   true,
        },
    },
})
```

## Redis Caching

For high-traffic applications, hitting the database on every request to validate sessions can become a bottleneck. Aegis supports **Redis caching** out of the box.

When Redis is enabled:
1.  **Read**: Session validation checks Redis first (milliseconds latency).
2.  **Write**: Session creation/updates write to both DB and Redis.
3.  **Invalidation**: Logout deletes from both; Redis keys have TTLs matching session expiry.

### Configuration

```go
auth := aegis.New(ctx, &config.Config{
    Session: &config.SessionConfig{
        Redis: &config.RedisConfig{
            Host: "localhost",
            Port: 6379,
            // Password: "...",
        },
    },
})
```

## Session Lifecycle

### Creation
Created automatically upon successful login (Email/Password or OAuth).

### Validation
Handled by `auth.AuthMiddleware()`. If valid, the `User` object is injected into the request context.

### Revocation (Logout)
Calling `/auth/logout` invalidates the session in the database and Redis, and clears the browser cookie.

### Refresh
When the access token expires, if a valid refresh token exists for that session, Aegis can automatically extend the session (if configured) or the client can request a refresh.
