Email and password authentication is the most common authentication method, allowing users to create accounts with an email address and password. Aegis provides built-in support with secure password hashing, email verification, and password reset flows.

## Quick Start

```go
import (
    "github.com/theinventorylib/aegis"
    "github.com/theinventorylib/aegis/config"
)

// Initialize Aegis with email/password support
cfg := config.Default().
    WithDB(db).
    WithRouter(router).
    WithSecret([]byte("your-secret-key"))

a, err := aegis.New(context.Background(), cfg)
if err != nil {
    log.Fatal(err)
}

// Mount auth routes
a.MountRoutes("/auth")

// Registration and login routes are automatically mounted at:
// POST /auth/default/signup
// POST /auth/default/login
// POST /auth/default/logout
```

## User Registration

### API Endpoint

```http
POST /auth/default/signup
Content-Type: application/json

{
  "name": "John Doe",
  "email": "john@example.com",
  "password": "SecurePass123!"
}
```

### Response

```json
{
  "success": true,
  "message": "Registration successful",
  "data": {
    "session": {"id": "sess_...", "token": "tkn_...", "expiresAt": "2024-01-16T10:30:00Z"},
    "user": {"id": "usr_...", "name": "John Doe", "email": "john@example.com", "emailVerified": false}
  }
}
```

### Programmatic Usage

```go
// Use the auth service's EmailPassword handler
result, err := a.GetAuthService().EmailPassword.Register(ctx, "John Doe", "john@example.com", "SecurePass123!")
if err != nil {
    // Handle error (duplicate email, weak password, etc.)
}
```

::callout{icon="i-heroicons-information-circle" color="blue"}
IP address and user agent are automatically extracted from the request context when using the HTTP handlers. No need to pass them manually.
::

## Password Security

### Argon2id Hashing

Aegis uses **Argon2id** for password hashing, which is the recommended algorithm by OWASP and winner of the Password Hashing Competition.

**Default Parameters:**
- Memory: 64 MB
- Iterations: 1
- Parallelism: 4
- Salt Length: 16 bytes
- Key Length: 32 bytes

```go
// Passwords are automatically hashed during registration
// You can customize the hashing parameters:
cfg := config.Default().
    WithArgon2Memory(128 * 1024). // 128 MB
    WithArgon2Time(4).            // 4 iterations
    WithArgon2Threads(4)          // 4 parallel threads
```

### Password Validation

Aegis validates passwords during registration to ensure minimum security:

```go
// Default validation rules:
// - Minimum length: 8 characters
// - Maximum length: 72 characters (bcrypt compatibility)
// - No other restrictions by default

// You can implement custom validation:
type CustomValidator struct{}

func (v *CustomValidator) ValidatePassword(password string) error {
    if len(password) < 12 {
        return errors.New("password must be at least 12 characters")
    }
    
    // Add your custom rules (uppercase, numbers, special chars, etc.)
    return nil
}

// You can configure a custom password policy:
cfg := config.Default().
    WithPasswordPolicy(&core.PasswordPolicy{
        MinLength:      12,
        RequireUpper:   true,
        RequireLower:   true,
        RequireNumber:  true,
        RequireSpecial: true,
    })
```

## Email Verification

::callout{icon="i-heroicons-exclamation-triangle" color="amber"}
Email verification is **not enabled by default**. You must configure an email provider to send verification emails.
::

### Enabling Email Verification

```go
import "github.com/theinventorylib/aegis/plugins/emailotp"

// Configure email provider (SMTP, SendGrid, etc.)
emailPlugin := emailotp.New(&emailotp.Config{
    Provider: emailotp.SMTP{
        Host:     "smtp.gmail.com",
        Port:     587,
        Username: "your-email@gmail.com",
        Password: "your-app-password",
    },
    RequireVerification: true, // Enforce email verification
    CodeExpiry:         15 * time.Minute,
})

// Register plugin
a.Use(ctx, emailPlugin)
```

### Verification Flow

1. **User registers** → Account created with `email_verified: false`
2. **Verification email sent** → Contains 6-digit code or magic link
3. **User verifies** → Submits code via `/auth/verify-email`
4. **Account activated** → `email_verified: true`

### Verification Endpoint

```http
POST /auth/verify-email
Content-Type: application/json

{
  "email": "john@example.com",
  "code": "123456"
}
```

## Password Reset

### Request Reset

```http
POST /auth/forgot-password
Content-Type: application/json

{
  "email": "john@example.com"
}
```

Response always returns `200 OK` to prevent email enumeration:

```json
{
  "message": "If the email exists, a reset link has been sent"
}
```

### Reset with Token

```http
POST /auth/reset-password
Content-Type: application/json

{
  "token": "reset_token_from_email",
  "new_password": "NewSecurePass456!"
}
```

### Security Features

- **Rate limiting**: Prevents brute force attacks (default: 5 attempts per hour)
- **Token expiry**: Reset tokens expire after 1 hour
- **One-time use**: Tokens are invalidated after successful reset
- **Email enumeration protection**: Always returns success response

## Account Lockout

Protect against brute force attacks with automatic account lockout:

```go
cfg := config.Default().
    WithRateLimiting(5, time.Minute)  // 5 requests per minute window
```

When an account is locked:

```json
{
  "error": "account_locked",
  "message": "Too many failed login attempts. Try again in 28 minutes.",
  "retry_after": "2024-01-15T11:00:00Z"
}
```

## Session Management

After successful login, Aegis automatically:

1. **Creates session** in database
2. **Sets HTTP-only cookie** with session token
3. **Logs authentication event** (IP, user agent, timestamp)
4. **Returns session data** in response

See the [Sessions](/concepts/sessions) documentation for details on session lifecycle, refresh tokens, and multi-device management.

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/auth/default/signup` | Create new user account |
| `POST` | `/auth/default/login` | Authenticate user |
| `POST` | `/auth/default/logout` | End current session |

## Configuration Options

```go
// Configuration is set via builder methods on config.Config:
cfg := config.Default().
    // Argon2id Password Hashing
    WithArgon2Time(1).           // Iterations (default: 1)
    WithArgon2Memory(64 * 1024). // Memory in KB (default: 64 MB)
    WithArgon2Threads(4).        // Parallel threads (default: 4)

    // Rate Limiting
    WithRateLimiting(5, time.Minute). // 5 requests per minute

    // Session
    WithSessionExpiry(24 * time.Hour).  // Session duration (default: 24h)
    WithRefreshExpiry(7 * 24 * time.Hour). // Refresh token (default: 7d)

    // Password Policy
    WithPasswordPolicy(&core.PasswordPolicy{
        MinLength:      8,
        RequireUpper:   false,
        RequireLower:   false,
        RequireNumber:  false,
        RequireSpecial: false,
    })
```

## Best Practices

1. **Use HTTPS in production** - Never send passwords over unencrypted connections
2. **Enable email verification** - Prevent fake accounts and verify user ownership
3. **Implement rate limiting** - Protect against brute force attacks
4. **Use strong secrets** - Generate cryptographically secure secret keys
5. **Monitor failed logins** - Track and alert on suspicious activity
6. **Enforce password policies** - Require strong passwords (length, complexity)
7. **Implement account lockout** - Temporarily disable accounts after failed attempts
8. **Log authentication events** - Maintain audit trail for security

## Troubleshooting

### "Invalid credentials" on correct password

- Check if account is locked due to failed attempts
- Verify email case sensitivity (Aegis uses case-insensitive email matching)
- Ensure database connection is working

### Passwords not hashing correctly

- Verify Argon2id parameters are not too low
- Check available system memory
- Ensure `crypto/rand` is available (required for salt generation)

### Email verification not working

- Confirm email plugin is registered
- Check SMTP credentials and connectivity
- Verify email provider allows app passwords
- Check spam folder for verification emails

### Session not persisting

- Verify cookies are enabled in browser
- Check `Secure` flag matches HTTPS usage (development vs production)
- Confirm `SameSite` attribute allows your usage pattern
- Ensure session is not expired
