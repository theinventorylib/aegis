# JWT Plugin

The JWT (JSON Web Token) plugin provides stateless authentication using industry-standard JWT tokens with **RSA signing** and database-backed key management.

## Features

- **RSA Signing**: Uses RS256 algorithm with secure key management
- **Key Rotation**: Automatic key rotation with configurable intervals
- **JWKS Endpoint**: Standard `.well-known/jwks.json` endpoint for public key discovery
- **Token Pairing**: Short-lived access tokens + long-lived refresh tokens
- **Revocation**: Redis-backed token blacklist
- **Stateless Verification**: Tokens can be verified by other services using public keys

## Installation

```bash
go get github.com/theinventorylib/aegis/plugins/jwt
```

## Configuration

```go
import (
    "context"
    "time"
    "github.com/theinventorylib/aegis"
    "github.com/theinventorylib/aegis/plugins/jwt"
)

// Configure JWT plugin
jwtPlugin := jwt.New(&jwt.Config{
    // Issuer identifier (e.g. your domain)
    Issuer: "yourapp.com",
    
    // Access tokens should be short-lived (security best practice)
    AccessTokenExpiry: 15 * time.Minute,
    
    // Refresh tokens can be long-lived
    RefreshTokenExpiry: 7 * 24 * time.Hour,
    
    // Rotate signing keys automatically every 24 hours
    KeyRotationInterval: 24 * time.Hour,
    
    // RSA Key Size (2048, 3072, or 4096)
    KeySize: 2048,
}, nil) // nil store uses default SQL storage (recommended)

// Register with Aegis
auth.Use(context.Background(), jwtPlugin)
```

## HTTP Endpoints

The plugin exposes the following endpoints:

| Method | Path | Description | Protected |
| --- | --- | --- | --- |
| `POST` | `/auth/jwt/token` | Generate new access/refresh pair | Yes |
| `POST` | `/auth/jwt/logout` | Revoke tokens (blacklist) | Yes |
| `POST` | `/auth/jwt/refreshToken` | Get new pair using refresh token | No |
| `GET` | `/.well-known/jwks.json` | Public JWK Set for verification | No |

## Key Management

This plugin manages RSA key pairs automatically:

1. **Storage**: Keys are stored in the `jwk_keys` table in your database.
2. **Rotation**: New keys are generated automatically based on `KeyRotationInterval`.
3. **Retention**: Old public keys are kept for `KeyRetention` period (default 30 days) to allow verifying older valid tokens.

### Database Schema

The plugin requires the `jwk_keys` table, which is automatically included in migrations:

```sql
CREATE TABLE jwk_keys (
    kid VARCHAR(255) PRIMARY KEY,
    key_data TEXT NOT NULL,      -- Encrypted JWK JSON
    algorithm VARCHAR(50) NOT NULL,
    use VARCHAR(50) NOT NULL,    -- 'sig' or 'enc'
    created_at TIMESTAMP NOT NULL,
    expires_at TIMESTAMP
);
```

## Revocation (Blacklist)

Token revocation (logout) works by adding the token ID (jti) to a Redis blacklist.

> [!IMPORTANT]
> Redis is **REQUIRED** for token revocation to work. If Redis is not configured in Aegis core, the `/logout` endpoint will succeed but tokens will not be blacklisted.

## Token Structure

Access tokens contains standard claims plus custom fields:

```json
{
  "iss": "yourapp.com",
  "sub": "user_123",
  "jti": "unique-token-id",
  "iat": 1707123456,
  "exp": 1707124356,
  "token_type": "access",
  "user_id": "user_123"
}
```

## Verifying Tokens in Other Services

Other services (like microservices or gateways) can verify tokens without connecting to the Aegis database:

1. Fetch public keys from `https://your-auth-server/.well-known/jwks.json`
2. Parse the JWT header to find the Key ID (`kid`)
3. Find the matching public key in the JWKS
4. Verify the signature (RS256)

### Go Example (using `lestrrat-go/jwx`)

```go
set, _ := jwk.Fetch(ctx, "https://your-auth-server/.well-known/jwks.json")
token, _ := jwt.ParseString(tokenString, jwt.WithKeySet(set))
```
