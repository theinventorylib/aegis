# Bearer Token Plugin

The Bearer Token plugin is a **lightweight feature toggle** that enables your application to accept session tokens via the `Authorization` header.

## Overview

By default, Aegis uses secure, HTTP-only cookies for session management. This is perfect for web applications but doesn't work for:
- Mobile applications (iOS/Android)
- CLI tools
- Single Page Applications (SPAs) not on the same domain
- Service-to-service communication

The Bearer plugin modifies the core authentication middleware to allow extracting the session token from the `Authorization: Bearer <token>` header.

## features

- **Zero Config**: Works out of the box with existing session infrastructure
- **No Extra Schema**: Reuses your existing `sessions` table
- **No Extra Routes**: No new endpoints to manage
- **Secure**: Reuses core session validation logic including expiration and revocation

## Installation

```bash
go get github.com/theinventorylib/aegis/plugins/bearer
```

## Usage

Register the plugin when initializing Aegis:

```go
package main

import (
    "context"
    "github.com/theinventorylib/aegis"
    "github.com/theinventorylib/aegis/core"
    "github.com/theinventorylib/aegis/plugins/bearer"
)

func main() {
    // ... setup db ...

    // Initialize Aegis
    auth := aegis.New(context.Background(), &config.Config{
        DB: db,
    })

    // Enable Bearer Auth Support
    // This tells Aegis to check the Authorization header for session tokens
    auth.Use(context.Background(), bearer.New(nil))
}
```

## Client Usage

Once enabled, clients can authenticate by sending their session token in the header:

```http
GET /api/profile
Authorization: Bearer <session_token>
```

### Getting the Token

Clients can obtain a session token via the standard login endpoints:

- `POST /auth/login` (Email/Password)
- `POST /auth/oauth/:provider/callback`

The response will contain the session token (often in the body or `Set-Cookie` header), which the client can then store securely (e.g., iOS Keychain) and use for subsequent requests.

## Security Considerations

- **HTTPS Required**: Bearer tokens are susceptible to interception. Always use HTTPS.
- **Storage**: Unlike cookies, bearer tokens must be stored insecurely by the client (localStorage, etc.) if not careful. recommend using secure storage mechanisms appropriate for the client platform.
- **CSRF**: Bearer tokens are generally immune to CSRF attacks since the browser doesn't automatically attach them to requests like cookies.
