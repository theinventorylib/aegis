## Plugin System

Aegis provides a powerful plugin system that allows you to extend functionality while keeping the core lightweight. Each plugin is self-contained with its own schema, models, and handlers.

## Installing Plugins

Plugins are Go packages that you import and register with Aegis:

```go
import (
    "github.com/theinventorylib/aegis"
    "github.com/theinventorylib/aegis/plugins/emailotp"
    "github.com/theinventorylib/aegis/plugins/oauth"
)

auth := aegis.New(&core.Config{...})

// Register plugins
auth.Use(emailotp.New(&emailotp.Config{...}))
auth.Use(oauth.New(&oauth.Config{...}))
```

## Official Plugins

Aegis includes 8 official plugins to cover common authentication scenarios:

### [Admin](/plugins/admin)
Administrative endpoints for user and session management.

### [Bearer](/plugins/bearer)
Bearer token authentication for API access and service-to-service communication.

### [Email OTP](/plugins/email-otp)
Email-based authentication with one-time passwords and email+password support.

### [JWT](/plugins/jwt)
JSON Web Token generation, validation, and rotation for stateless authentication.

### [OAuth](/plugins/oauth)
Social login with Google, GitHub, Facebook, Discord, and other OAuth providers.

### [OpenAPI](/plugins/openapi)
Interactive API documentation with Scalar UI.

### [Organizations](/plugins/organizations)
Multi-tenant organization and team management for SaaS applications.

### [SMS OTP](/plugins/sms-otp)
Phone number verification with SMS one-time passwords.

## Creating Custom Plugins

You can create your own plugins by implementing the `Plugin` interface:

```go
type Plugin interface {
    // Identity
    Name() string        // Plugin identifier (e.g., "sms", "oauth")
    Version() string     // Plugin version
    Description() string // Human-readable description

    // Lifecycle
    Init(ctx context.Context, a Aegis) error // Initialize plugin
    GetMigrations() []Migration              // Return migrations
    GetSchemas() []Schema                    // Return database schemas

    // Routing
    MountRoutes(router router.Router, prefix string) // Register HTTP routes

    // Metadata (Informational)
    Dependencies() []Dependency
    RequiresTables() []string
    ProvidesAuthMethods() []string
}
```

### Plugin Structure

A typical plugin has the following structure:

```
myplugin/
├── plugin.go          # Plugin interface implementation
├── config.go          # Configuration options
├── handlers.go        # HTTP handlers
├── models.go          # Data models
├── store.go           # Database operations
├── schema.go          # Database schema
└── migrations/        # Database migrations
    ├── postgres/
    └── mysql/
```

### Example Plugin

Here's a complete example of a custom plugin:

```go
package myplugin

import (
    "context"
    "github.com/theinventorylib/aegis/plugins"
    "github.com/theinventorylib/aegis/router"
)

// Plugin implements the plugins.Plugin interface
type Plugin struct {
    config *Config
    aegis  plugins.Aegis
}

// Config holds plugin configuration
type Config struct {
    Enabled bool
}

// New creates a new plugin instance
func New(config *Config) *Plugin {
    return &Plugin{config: config}
}

// Identity
func (p *Plugin) Name() string { return "myplugin" }
func (p *Plugin) Version() string { return "1.0.0" }
func (p *Plugin) Description() string { return "My Custom Plugin" }

// Init initializes the plugin
func (p *Plugin) Init(ctx context.Context, a plugins.Aegis) error {
    p.aegis = a
    return nil
}

// Routes returns the plugin's HTTP routes
func (p *Plugin) MountRoutes(r router.Router, prefix string) {
    r.Get(prefix + "/myplugin/hello", p.handleHello)
}

// Schema and Migrations (Empty for this example)
func (p *Plugin) GetMigrations() []plugins.Migration { return nil }
func (p *Plugin) GetSchemas() []plugins.Schema { return nil }

// Metadata
func (p *Plugin) Dependencies() []plugins.Dependency { return nil }
func (p *Plugin) RequiresTables() []string { return nil }
func (p *Plugin) ProvidesAuthMethods() []string { return nil }

// HTTP Handlers
func (p *Plugin) handleHello(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("Hello from MyPlugin!"))
}
```

### Plugin Capabilities

Plugins can:

- **Define Schema**: Add new tables and columns to the database
- **Register Routes**: Add HTTP endpoints to the Aegis router
- **Access Core Services**: Use session management, user store, etc.
- **Extend User Model**: Add additional fields via composition
- **Run Migrations**: Manage database schema changes
- **Validate Requirements**: Check that required tables and columns exist
- **Use Priority**: Control initialization order with `UseWithPriority()`

### Plugin Guidelines

1. **Isolation**: Keep plugins self-contained and independent
2. **Composition**: Extend core models via composition, not modification
3. **Migrations**: Include migrations for all schema changes
4. **Documentation**: Document all endpoints and configuration options
5. **Testing**: Write comprehensive tests for all functionality
6. **Validation**: Validate schema requirements during initialization
7. **Error Handling**: Return clear, actionable error messages

### Advanced Features

#### Schema Validation

Validate that required tables and columns exist:

```go
func (p *Plugin) Init(ctx context.Context, a *aegis.Aegis) error {
    requirements := []plugins.SchemaRequirement{
        plugins.ValidateTableExists("my_table"),
        plugins.ValidateColumnExists("my_table", "id"),
        plugins.ValidateColumnExists("my_table", "user_id"),
    }
    
    if err := a.ValidateSchemaRequirements(ctx, requirements); err != nil {
        return fmt.Errorf("schema validation failed: %w", err)
    }
    
    return nil
}
```

#### Plugin Priority

Control initialization order with priority (lower = earlier):

```go
// Initialize organizations plugin first
auth.UseWithPriority(ctx, orgsPlugin, 10)

// Other plugins use default priority (100)
auth.Use(ctx, myPlugin)
```

#### Accessing Core Services

Plugins can access core Aegis services:

```go
func (p *Plugin) handleCreate(w http.ResponseWriter, r *http.Request) {
    // Get current user from session
    user := core.GetUser(r.Context())
    
    // Access database
    db := p.aegis.DB()
    
    // Use session store
    session, _ := p.aegis.SessionStore().Get(r.Context(), token)
}
```

#### User Model Extension

Extend the User model via composition:

```go
type ExtendedUser struct {
    core.User           // Embed core user
    CustomField string  // Add custom fields
    Settings    map[string]interface{}
}

// EnrichUser adds plugin-specific fields
func (p *Plugin) EnrichUser(ctx context.Context, user *core.User) error {
    // Add custom data to user
    return nil
}
```

### Publishing Your Plugin

To share your plugin with the community:

1. **Structure**: Follow the standard plugin structure
2. **Documentation**: Include comprehensive README with examples
3. **Tests**: Write tests with good coverage
4. **Versioning**: Use semantic versioning
5. **Examples**: Provide working example applications
6. **License**: Include an appropriate license (MIT recommended)
