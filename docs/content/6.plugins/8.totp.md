---
title: TOTP
description: Time-based one-time password (RFC 6238) two-factor authentication with recovery codes.
---

The TOTP plugin adds authenticator-app two-factor authentication to Aegis. It
implements RFC 6238 (HMAC-SHA1) directly, stores the secret on the user, and
keeps per-session verification in its own table so sessions that have not
cleared the second factor can be restricted.

## Features

- **RFC 6238 TOTP**: 6-digit codes on a 30-second step, compatible with Google
  Authenticator, 1Password, Authy and similar apps
- **Pending enrollment**: a secret is inert until a code is confirmed, so a
  half-finished setup can never lock a user out
- **Single-use recovery codes**: hashed and consumed on use, stored as core
  verification tokens (no extra plugin table)
- **Per-session step-up**: sessions stay verified for a configurable TTL; rows
  cascade with the session, so logout and expiry cannot leave a flag behind
- **Middleware**: `RequireVerification` blocks requests until step-up completes
- **Audit**: enable/disable and verification failures are visible through the
  core audit pipeline

## Installation

```bash
go get github.com/theinventorylib/aegis/v2/plugins/totp
```

## Configuration

```go
import (
    "time"
    "github.com/theinventorylib/aegis/v2/plugins/totp"
)

totpPlugin := totp.New(&totp.Config{
    Issuer:        "MyApp",        // label shown in authenticator apps
    Digits:        6,              // code length
    Period:        30 * time.Second,
    Skew:          1,              // accepted steps before/after now
    RecoveryCodes: 10,             // 0 disables recovery codes
    SessionTTL:    12 * time.Hour, // how long a step-up lasts
}, nil) // nil store uses default SQL storage

a, _ := aegis.New(ctx, cfg)
a.Use(ctx, totpPlugin)
a.MountRoutes("/auth")
```

### Configuration Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `Issuer` | `string` | `"Aegis"` | Label shown in authenticator apps |
| `Digits` | `int` | 6 | Code length |
| `Period` | `time.Duration` | 30s | Time step |
| `Skew` | `int` | 1 | Accepted steps before/after now (clock drift) |
| `SecretBytes` | `int` | 20 | Entropy of generated secrets |
| `RecoveryCodes` | `int` | 10 | Single-use recovery codes generated on enable |
| `SessionTTL` | `time.Duration` | 12h | How long a verified session stays verified |

## Database Schema

The plugin extends the `user` table with:

| Column | Type | Description |
|--------|------|-------------|
| `totp_secret` | TEXT | Base32 secret; NULL when no enrollment |
| `totp_enabled` | INTEGER | 1 only after a code from the pending secret is confirmed |

And adds:

| Table | Description |
|-------|-------------|
| `totp_session` | `session_id` → `verified_at`; cascades with the session |

Recovery codes are stored in the core `verification` table (type
`totp_recovery`, identifier = user ID), hashed and single-use.

## HTTP Endpoints

| Method | Path | Description | Auth Required |
|--------|------|-------------|---------------|
| POST | `/totp/setup` | Start enrollment; returns secret + otpauth URL | Yes |
| POST | `/totp/enable` | Confirm a code, activate TOTP, return recovery codes | Yes |
| POST | `/totp/disable` | Remove the credential and session verifications | Yes |
| POST | `/totp/verify` | Step-up the current session with a code | Yes |
| POST | `/totp/recovery-codes` | Regenerate recovery codes (requires a TOTP code) | Yes |
| GET | `/totp/status` | Enabled + current-session verification state | Yes |

### Setup

```http
POST /auth/totp/setup
Authorization: Bearer <token>
```

```json
{
  "secret": "JBSWY3DPEHPK3PXP",
  "otpauth_url": "otpauth://totp/MyApp:user_123?secret=...&issuer=MyApp"
}
```

### Enable

```http
POST /auth/totp/enable
Authorization: Bearer <token>
Content-Type: application/json

{ "code": "123456" }
```

```json
{ "recovery_codes": ["ABCDEFGH", "IJKLMNOP", "..."] }
```

Recovery codes are shown once. Store them hashed at rest (the plugin already
does); display them to the user exactly this one time.

### Verify (step-up)

```http
POST /auth/totp/verify
Authorization: Bearer <token>
Content-Type: application/json

{ "code": "123456" }
```

Use `{ "code": "ABCDEFGH", "recovery": true }` for a recovery code. On success
the current session is marked verified for `SessionTTL`.

## Programmatic API

```go
plugin, ok := aegis.GetPluginTyped[*totp.Plugin](a, "totp")
if !ok {
    log.Fatal("TOTP plugin not registered")
}

setup, err := plugin.Setup(ctx, userID)            // secret + otpauth URL
codes, err := plugin.Enable(ctx, userID, code)     // activates + recovery codes
ok, err := plugin.Verify(ctx, userID, code)        // code check
ok, err := plugin.VerifyRecoveryCode(ctx, userID, code)
err = plugin.Disable(ctx, userID)
enabled, err := plugin.IsEnabled(ctx, userID)
err = plugin.MarkSessionVerified(ctx, sessionID, userID)
verified := plugin.IsSessionVerified(ctx, sessionID, userID)
```

## Restricting Routes

Mount `RequireVerification` after authentication on any route that should wait
for the second factor:

```go
r.Group(func(protected chi.Router) {
    protected.Use(core.RequireAuthMiddleware(sessionService))
    protected.Use(totpPlugin.RequireVerification)
    protected.Get("/api/giving", givingHandler)
})
```

The middleware answers `403` with `{"error": "two-factor verification required",
"data": {"code": "totp_required"}}` until `/totp/verify` succeeds. It never
blocks unauthenticated requests, so it composes with the auth middleware.

## Security Considerations

- Secrets are stored as plaintext `totp_secret` values, matching how Aegis
  stores OAuth provider tokens. Restrict database read access accordingly.
- Enrollment refuses to replace a credential while TOTP is enabled, so a
  hijacked session cannot silently re-enroll the account.
- Recovery-code regeneration requires a valid TOTP code, not just a session.
- Disabling TOTP clears the secret, all session verifications and outstanding
  recovery codes.
- Codes are compared in constant time and accept `Skew` steps to tolerate clock
  drift.
