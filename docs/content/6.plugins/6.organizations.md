The Organizations plugin enables multi-tenancy with organizations, teams, roles, and member management. Ideal for SaaS applications, collaboration platforms, and enterprise software.

## Features

- **Organization Management**: Create, update, and delete organizations (workspaces, tenants)
- **Team Support**: Organize members into teams within organizations
- **Role-Based Permissions**: Owner, Admin, and Member roles at both org and team level
- **Member Management**: Add, remove, and update member roles
- **User Enrichment**: Automatically adds an `organizations` key to the enriched user response containing a list of orgs with `id`, `name`, and `slug` fields
- **OpenAPI Integration**: All endpoints documented in the OpenAPI spec

## Installation

```bash
go get github.com/theinventorylib/aegis/v2/plugins/organizations
```

## Configuration

```go
import (
    "context"
    "github.com/theinventorylib/aegis/v2"
    "github.com/theinventorylib/aegis/v2/plugins/organizations"
    "github.com/theinventorylib/aegis/v2/plugins"
)

// Create with default store and built-in roles
orgsPlugin := organizations.New(nil, nil, plugins.DialectPostgres)

// Or with custom roles, a custom store, and email templates
orgsPlugin := organizations.New(&organizations.Config{
    OrgRoles: map[string]organizations.RoleDefinition{
        "billing": {Permissions: []organizations.Permission{
            organizations.PermOrgView,
            organizations.PermMemberView,
        }},
    },
    TeamRoles: map[string]organizations.RoleDefinition{
        "reviewer": {Permissions: []organizations.Permission{
            organizations.PermTeamView,
        }},
    },
    InvitationSubject:      "Join our team!",
    InvitationBodyTemplate: "Click here to accept: %s",
}, myCustomStore, plugins.DialectPostgres)

// Register with Aegis
a, _ := aegis.New(ctx, cfg)
a.Use(ctx, orgsPlugin)

// Mount routes (org endpoints available at /auth/organizations/*)
a.MountRoutes("/auth")
```

### Config Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `OrgRoles` | `map[string]RoleDefinition` | `nil` | Overrides/extends org roles. Same key replaces a built-in (`owner`, `admin`, `member`); new keys add custom roles. |
| `TeamRoles` | `map[string]RoleDefinition` | `nil` | Overrides/extends team roles (`lead`, `member`). Same semantics. |
| `InvitationSubject` | `string` | `"You're invited!"` | Subject line for invitation emails |
| `InvitationBodyTemplate` | `string` | `"You have been invited.\n\nAccept your invitation here: %s"` | Body template (use `%s` for the accept URL) |

### Custom Roles and Permissions

Roles are strings; authority comes from the **permissions** a role grants, so
built-in handlers honor custom roles. Define a role and the capabilities it
grants:

```go
orgsPlugin := organizations.New(&organizations.Config{
    OrgRoles: map[string]organizations.RoleDefinition{
        "billing": {Permissions: []organizations.Permission{
            organizations.PermOrgView,
            organizations.PermMemberView,
            organizations.PermInvitationManage,
        }},
    },
}, nil, plugins.DialectPostgres)
```

Roles can also be created per organization at runtime through the API (persisted
in `organization_role`). Compiled definitions always win on name collisions, so
a tenant can never shadow a built-in role.

Available permissions:

| Permission | Grants |
|------------|--------|
| `PermOrgView` | View the organization, members, and teams |
| `PermOrgManage` | Update organization settings |
| `PermOrgDelete` | Delete the organization |
| `PermMemberView` | List members |
| `PermMemberManage` | Add/remove members |
| `PermMemberAssignRoles` | Change a member's org role |
| `PermTeamView` | View teams and team members |
| `PermTeamManage` | Create/update/delete teams |
| `PermTeamMemberManage` | Add/update/remove team members |
| `PermInvitationManage` | Create/list/cancel invitations |

The built-in roles map to these permissions as follows:

| Role | Permissions |
|------|-------------|
| `owner` | All |
| `admin` | All except `PermOrgDelete` |
| `member` | `PermOrgView`, `PermMemberView`, `PermTeamView` |
| `lead` (team) | `PermTeamView`, `PermTeamMemberManage` |
| `member` (team) | `PermTeamView` |

### Granting Authority

A member who can write permissions (`member:assign_roles`) or define roles
(`org:manage`) can only pass on the framework permissions they already hold.
An `admin` therefore cannot grant `org:delete` — directly, through an override,
or by defining a custom role for it. App-defined permission strings are not
capped: the application owns their meaning. The owner's role and permission
overrides are protected from change, so an admin cannot demote or lock out the
owner.

Check permissions programmatically or in middleware:

```go
// Programmatic
ok, err := orgsPlugin.HasOrgPermission(ctx, userID, orgID, organizations.PermMemberManage)
teamOk, err := orgsPlugin.HasTeamPermission(ctx, userID, teamID, organizations.PermTeamMemberManage)

// Middleware (prefer this over RequireOrgRole so custom roles are honored)
r.PUT("/organizations/:id",
    requireAuth(orgsPlugin.RequireOrgPermission(organizations.PermOrgManage)(handler)))
r.POST("/teams/:teamId/members",
    requireAuth(orgsPlugin.RequireTeamPermission(organizations.PermTeamMemberManage)(handler)))
```

`RequireOrgRole` / `RequireTeamRole` remain for explicit role-name checks.
`OrgRoles()` / `TeamRoles()` return the compiled (built-in + configured)
definitions; `ListRoles(ctx, orgID)` returns the per-organization catalog
including persisted custom roles.

## Database Schema

### Organizations

```sql
CREATE TABLE organization (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    slug TEXT NOT NULL UNIQUE,
    disabled INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

### Members

```sql
CREATE TABLE members (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
    organization_id TEXT NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
    role TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE(user_id, organization_id)
);
```

### Member Permission Overrides

Per-member adjustments on top of the role's permissions. `deny` removes a
permission the role would grant; `grant` adds one it does not. `deny` wins over
`grant`, and neither applies to users who are not members. A `grant` is capped
at the actor's own framework permissions (see
[Granting Authority](#granting-authority)), and the owner's overrides cannot be
changed through the API.

```sql
CREATE TABLE member_permission_override (
    id TEXT PRIMARY KEY,
    organization_id TEXT NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
    user_id TEXT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
    permission TEXT NOT NULL,
    effect TEXT NOT NULL CHECK (effect IN ('grant', 'deny')),
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE (organization_id, user_id, permission)
);
```

Every authorization check (`HasOrgPermission`, `RequireOrgPermission`) applies
the overrides, so they cover the built-in handlers and application middleware
alike.

### Custom Roles

Organization-specific role definitions created through the API. Permissions are
stored as a JSON array. Compiled roles (built-in and `Config.OrgRoles`) are not
in this table and cannot be edited or shadowed.

```sql
CREATE TABLE organization_role (
    id TEXT PRIMARY KEY,
    organization_id TEXT NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    permissions TEXT NOT NULL DEFAULT '[]',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE (organization_id, name)
);
```

### Teams

```sql
CREATE TABLE team (
    id TEXT PRIMARY KEY,
    organization_id TEXT NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    description TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

### Team Members

```sql
CREATE TABLE team_member (
    id TEXT PRIMARY KEY,
    team_id TEXT NOT NULL REFERENCES team(id) ON DELETE CASCADE,
    user_id TEXT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
    role TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE(team_id, user_id)
);
```

### Invitations

```sql
CREATE TABLE invitation (
    id TEXT PRIMARY KEY,
    organization_id TEXT NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
    team_id TEXT REFERENCES team(id) ON DELETE CASCADE,
    email TEXT NOT NULL,
    role TEXT NOT NULL,
    inviter_id TEXT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
    token_hash TEXT NOT NULL UNIQUE,
    status TEXT NOT NULL DEFAULT 'pending',
    expires_at TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE INDEX idx_invitation_org_status ON invitation(organization_id, status);
CREATE INDEX idx_invitation_token_hash ON invitation(token_hash);
CREATE INDEX idx_invitation_status_expires ON invitation(status, expires_at);
```

## HTTP Endpoints

All organization endpoints require authentication. Role-based access is enforced where noted.

### Organizations

#### Create Organization

The authenticated user becomes the owner automatically.

```http
POST /auth/organizations
Authorization: Bearer <token>
Content-Type: application/json

{
  "name": "Acme Corp",
  "slug": "acme-corp"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Organization display name |
| `slug` | string | Yes | URL-friendly unique identifier |

**Response (201):**

```json
{
  "success": true,
  "message": "Organization created successfully",
  "data": {
    "id": "org_abc123",
    "name": "Acme Corp",
    "slug": "acme-corp",
    "createdAt": "2024-02-15T10:00:00Z",
    "updatedAt": "2024-02-15T10:00:00Z"
  }
}
```

#### List User's Organizations

Get all organizations the current user belongs to.

```http
GET /auth/organizations
Authorization: Bearer <token>
```

**Response (200):**

```json
{
  "items": [
    {
      "id": "org_abc123",
      "name": "Acme Corp",
      "slug": "acme-corp",
      "createdAt": "2024-02-15T10:00:00Z",
      "updatedAt": "2024-02-15T10:00:00Z"
    }
  ],
  "totalCount": 1,
  "page": 1,
  "offset": 0,
  "limit": 20
}
```

Supports `page` and `limit` query parameters for pagination.

#### Get Organization

Requires membership in the organization.

```http
GET /auth/organizations/:id
Authorization: Bearer <token>
```

#### Update Organization

Requires **owner** or **admin** role.

```http
PUT /auth/organizations/:id
Authorization: Bearer <token>
Content-Type: application/json

{
  "name": "Acme Corporation",
  "slug": "acme-corporation"
}
```

#### Delete Organization

Requires **owner** role.

```http
DELETE /auth/organizations/:id
Authorization: Bearer <token>
```

Requires **owner** or **admin** role.

```http

Authorization: Bearer <token>

{
  "userId": "user_xyz789",

```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `userId` | string | Yes | User ID to add |

```http

```

Requires `member:assign_roles` (owner/admin). The owner's role cannot be changed.

```http
PATCH /auth/organizations/:id/members/:userId
Authorization: Bearer <token>
Content-Type: application/json

{
  "role": "admin"
}
```

#### Remove Member

Requires **owner** or **admin** role.

```http
DELETE /auth/organizations/:id/members/:userId
Authorization: Bearer <token>
```

#### Get My Permissions

Returns the authenticated user's own role, raw overrides and the resolved
effective permission set. Any member can read their own authorization (no
special permission required); non-members get `403`.

```http
GET /auth/organizations/:id/permissions
Authorization: Bearer <token>
```

```json
{
  "role": "member",
  "overrides": [],
  "permissions": ["member:view", "org:view", "team:view"]
}
```

#### Get Member Permissions

Returns the member's role, raw overrides and the resolved effective permission
set. Requires `member:assign_roles` (owner/admin).

```http
GET /auth/organizations/:id/members/:userId/permissions
Authorization: Bearer <token>
```

```json
{
  "role": "admin",
  "overrides": [
    { "permission": "member:manage", "effect": "deny" },
    { "permission": "view_giving", "effect": "grant" }
  ],
  "permissions": ["member:view", "org:view", "team:view", "view_giving"]
}
```

#### List Members' Permissions

Returns every member's role, overrides and resolved effective permissions, for
an admin overview. Paginated with `page`/`limit`. Requires `member:assign_roles`
(owner/admin).

```http
GET /auth/organizations/:id/members/permissions
Authorization: Bearer <token>
```

```json
{
  "items": [
    {
      "userId": "user_123",
      "role": "admin",
      "overrides": [],
      "permissions": ["member:manage", "member:view", "org:manage", "org:view", "team:manage", "team:view", "team_member:manage"]
    }
  ],
  "totalCount": 1,
  "page": 1,
  "offset": 0,
  "limit": 20
}
```

> This resolves permissions per member, so a page of `N` costs O(N) lookups.
> Keep the default page size for large organizations.

#### Replace Member Permissions

Replaces the override set (send an empty list to clear it). Requires
`member:assign_roles` (owner/admin). Duplicate permissions are rejected, grants
are capped at the actor's own framework permissions, and the owner's overrides
cannot be changed.

```http
PUT /auth/organizations/:id/members/:userId/permissions
Authorization: Bearer <token>
Content-Type: application/json

{
  "overrides": [
    { "permission": "member:manage", "effect": "deny" },
    { "permission": "view_giving", "effect": "grant" }
  ]
}
```

### Roles

Custom roles are per organization. Listing requires any member; create, update
and delete require `org:manage` (owner/admin). Compiled role names are reserved,
and a role still assigned to members cannot be deleted.

```http
GET    /auth/organizations/:id/roles
POST   /auth/organizations/:id/roles
PUT    /auth/organizations/:id/roles/:name
DELETE /auth/organizations/:id/roles/:name
Authorization: Bearer <token>
```

```json
// POST body
{
  "name": "billing",
  "permissions": ["org:view", "member:view", "view_giving"]
}
```

The create/update response returns the role with `custom: true`; listed compiled
roles carry `custom: false`.

### Invitations

#### Create Invitation

Invites a user via email. Requires **owner** or **admin** role. The raw token is returned exactly once — deliver it to the invitee via your own channel (email, etc.).

```http
POST /auth/organizations/:id/invitations
Authorization: Bearer <token>
Content-Type: application/json

{
  "email": "newuser@example.com",
  "role": "member"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | string | Yes | Invitee email address |
| `role` | string | Yes | Role on acceptance: `admin` or `member` |
| `teamId` | string | No | Directly invite to a specific team |
| `expiresIn` | string | No | Duration (e.g. `"72h"`), defaults to `168h` (7 days) |

**Response (201):**

```json
{
  "success": true,
  "message": "Invitation created",
  "data": {
    "id": "inv_abc123",
    "organizationId": "org_xyz789",
    "teamId": null,
    "email": "newuser@example.com",
    "role": "member",
    "token": "abc123def456...",
    "status": "pending",
    "expiresAt": "2024-01-08T00:00:00Z",
    "createdAt": "2024-01-01T00:00:00Z",
    "updatedAt": "2024-01-01T00:00:00Z"
  }
}
```

Team-level invites are created the same way, by including a `teamId` field in the body.

## Programmatic API

All organization operations are available as Go methods on the plugin instance. Use these for server-side logic, background jobs, CLI tools, or custom handlers requiring multi-tenant functionality.

### Getting the Plugin Instance

```go
// Type-safe retrieval (recommended)
orgsPlugin, ok := aegis.GetPluginTyped[*organizations.Plugin](a, "organizations")
if !ok {
    log.Fatal("Organizations plugin not registered")
}

// Via GetPlugin with type assertion
plugin, ok := a.GetPlugin("organizations")
if ok {
    orgsPlugin := plugin.(*organizations.Plugin)
}
```

### Organization Methods

#### CreateOrganization

Create a new organization with the creator automatically assigned as owner.

```go
func CreateOrganization(ctx context.Context, name, slug, ownerID string) (*Organization, error)
```

**Parameters:**
- `ctx` — Request context for cancellation and tracing
- `name` — Organization display name (e.g., "Acme Corporation")
- `slug` — URL-friendly unique identifier (e.g., "acme-corp")
- `ownerID` — ID of the user creating the organization (becomes owner)

**Returns:**
- `*Organization` — Created organization with ID, timestamps
- `error` — Validation errors (duplicate slug) or database errors

**Behavior:**
- Creates organization record
- Automatically adds creator as organization member with "owner" role
- Slug must be unique across all organizations
- No minimum/maximum member limits enforced

**Example:**
```go
org, err := orgsPlugin.CreateOrganization(ctx, "Acme Corp", "acme-corp", "user_123")
if err != nil {
    if strings.Contains(err.Error(), "duplicate") {
        return fmt.Errorf("slug already taken")
    }
    return fmt.Errorf("failed to create organization: %w", err)
}

log.Info("Organization created", "org_id", org.ID, "slug", org.Slug)
```

#### GetOrganization

Retrieve organization details by ID.

```go
func GetOrganization(ctx context.Context, id string) (Organization, error)
```

**Parameters:**
- `ctx` — Request context
- `id` — Organization identifier

**Returns:**
- `Organization` — Organization object with name, slug, timestamps
- `error` — `sql.ErrNoRows` if not found, database errors

**Example:**
```go
org, err := orgsPlugin.GetOrganization(ctx, "org_abc123")
if err != nil {
    return fmt.Errorf("organization not found: %w", err)
}
fmt.Printf("Organization: %s (slug: %s)\n", org.Name, org.Slug)
```

#### UpdateOrganization

Update organization name and slug.

```go
func UpdateOrganization(ctx context.Context, id, name, slug string) error
```

**Parameters:**
- `ctx` — Request context
- `id` — Organization to update
- `name` — New display name
- `slug` — New URL slug (must be unique)

**Returns:**
- `error` — Validation errors (duplicate slug) or database errors

**Behavior:**
- Updates both name and slug atomically
- Fails if new slug conflicts with existing organization
- Does not validate user permissions (implement in your handlers)

**Example:**
```go
err := orgsPlugin.UpdateOrganization(ctx, "org_abc", "New Name", "new-slug")
if err != nil {
    return fmt.Errorf("failed to update organization: %w", err)
}
```

#### DeleteOrganization

Soft-delete an organization (sets the disabled flag, hiding it from all queries).

```go
func DeleteOrganization(ctx context.Context, id string) error
```

**Parameters:**
- `ctx` — Request context
- `id` — Organization to delete

**Returns:**
- `error` — Database errors

**Warning:**
- Marks the organization as disabled (soft-delete) — all queries filter `disabled = 0`
- Related records (members, teams, invitations) are preserved but hidden via the same filter
- Does not delete user accounts (only memberships)

**Example:**
```go
// Confirm before deletion
err := orgsPlugin.DeleteOrganization(ctx, "org_to_delete")
if err != nil {
    return fmt.Errorf("failed to delete organization: %w", err)
}
log.Warn("Organization permanently deleted", "org_id", "org_to_delete")
```

#### GetUserOrganizations

List all organizations a user belongs to with their roles.

```go
func GetUserOrganizations(ctx context.Context, userID string, offset, limit int) ([]*Organization, int, error)
```

**Parameters:**
- `ctx` — Request context
- `userID` — User identifier
- `offset` — Pagination offset
- `limit` — Page size

**Returns:**
- `[]*Organization` — Organizations the user is a member of


### Authorization Methods

#### IsOrganizationMember

Check if a user is a member of an organization (any role).

```go
func IsOrganizationMember(ctx context.Context, userID, orgID string) bool
```

**Parameters:**
- `ctx` — Request context
- `userID` — User identifier
- `orgID` — Organization identifier

**Returns:**
- `bool` — `true` if user has any role in the organization

**Use cases:**
- Basic access control for organization resources
- Checking if user can view organization data
- Middleware authorization

### Role and Permission Methods

Custom roles and per-member overrides are managed with these methods. The HTTP
handlers apply the actor-authority cap and the owner guard before delegating to
the write methods; the programmatic methods themselves are trusted application
code and do not.

#### ListRoles

```go
func (p *Plugin) ListRoles(ctx context.Context, orgID string) ([]RoleInfo, error)
```

Returns the compiled roles (built-in plus `Config.OrgRoles`) merged with the
organization's persisted custom roles. Compiled definitions win on name
collisions.

#### CreateRole / UpdateRole / DeleteRole

```go
func (p *Plugin) CreateRole(ctx context.Context, orgID, name string, permissions []Permission) (RoleInfo, error)
func (p *Plugin) UpdateRole(ctx context.Context, orgID, name string, permissions []Permission) (RoleInfo, error)
func (p *Plugin) DeleteRole(ctx context.Context, orgID, name string) error
```

`CreateRole`/`UpdateRole` reject compiled role names (`ErrRoleReserved`),
duplicates (`ErrRoleExists`) and unknown roles (`sql.ErrNoRows`); `DeleteRole`
refuses a role still assigned to members (`ErrRoleInUse`).

#### GetMemberPermissions

```go
func (p *Plugin) GetMemberPermissions(ctx context.Context, userID, orgID string) (MemberPermissions, error)
```

Resolves the member's role plus overrides into an effective permission set.

#### MemberPermissionOverrides / SetMemberPermissionOverrides

```go
func (p *Plugin) MemberPermissionOverrides(ctx context.Context, orgID, userID string) ([]orgtypes.MemberPermissionOverride, error)
func (p *Plugin) SetMemberPermissionOverrides(ctx context.Context, orgID, userID string, overrides []orgtypes.MemberPermissionOverride) error
```

`SetMemberPermissionOverrides` replaces the override set (pass an empty slice to
clear it). It rejects a missing permission (`ErrPermissionRequired`), an unknown
effect (`ErrInvalidEffect`) and duplicates (`ErrDuplicatePermission`), confirms
the target is a member (`sql.ErrNoRows` otherwise), and fills in IDs and
timestamps in place. Replacement is delete-then-insert: a failure part-way
through leaves a partial set, corrected by re-sending the desired list.

```go
err := orgsPlugin.SetMemberPermissionOverrides(ctx, "org_abc", "user_123", []orgtypes.MemberPermissionOverride{
    {Permission: string(organizations.PermMemberManage), Effect: orgtypes.PermissionEffectDeny},
    {Permission: "view_giving", Effect: orgtypes.PermissionEffectGrant},
})
```

## Security Considerations

- **Role enforcement**: All mutating operations validate the caller's role before proceeding
- **Owner protection**: Organizations must always have at least one owner
- **Soft-delete**: Deleting an organization sets a disabled flag — related records are preserved but hidden from queries
- **Input sanitization**: All inputs (names, slugs) are sanitized before processing
- **Slug uniqueness**: Organization slugs are unique across the platform

## Example Integration

```go
package main

import (
    "context"
    "database/sql"
    "net/http"

    "github.com/go-chi/chi/v5"
    "github.com/theinventorylib/aegis/v2"
    "github.com/theinventorylib/aegis/v2/config"
    "github.com/theinventorylib/aegis/v2/core"
    "github.com/theinventorylib/aegis/v2/plugins"
    "github.com/theinventorylib/aegis/v2/plugins/organizations"
    "github.com/theinventorylib/aegis/v2/router/routers"
)

func main() {
    ctx := context.Background()
    db, _ := sql.Open("postgres", "postgres://localhost/myapp?sslmode=disable")
    r := chi.NewRouter()

    cfg := config.Default().
        WithDB(db).
        WithRouter(routers.NewChiRouter(r)).
        WithSecret([]byte("your-32-byte-secret-key-here!!!!"))

    a, _ := aegis.New(ctx, cfg)

    // Register organizations plugin
    orgsPlugin := organizations.New(nil, nil, plugins.DialectPostgres)
    a.Use(ctx, orgsPlugin)

    // Mount all routes
    a.MountRoutes("/auth")
    r.Use(a.AuthMiddleware())

    // Custom org-scoped endpoint using programmatic API
    r.Route("/api/orgs/{orgId}", func(r chi.Router) {
        r.Use(func(next http.Handler) http.Handler {
            return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
                orgID := core.GetSanitizedPathParam(r, "orgId")
                user := core.GetUser(r.Context())
                if user == nil {
                    http.Error(w, "Unauthorized", http.StatusUnauthorized)
                    return
                }
                isMember, _ := orgsPlugin.IsOrganizationMember(r.Context(), orgID, user.ID)
                if !isMember {
                    http.Error(w, "Forbidden", http.StatusForbidden)
                    return
                }
                next.ServeHTTP(w, r)
            })
        })
        r.Get("/dashboard", func(w http.ResponseWriter, r *http.Request) {
            orgID := core.GetSanitizedPathParam(r, "orgId")
            members, _ := orgsPlugin.ListOrganizationMembers(r.Context(), orgID)
            teams, _ := orgsPlugin.ListTeams(r.Context(), orgID)

            core.WriteJSON(w, http.StatusOK, &core.Response{
                Success: true,
                Data: &OrganizationDashboardResponse{
                    Members: members,
                    Teams:   teams,
                },
            })
        })
    })

    http.ListenAndServe(":8080", r)
}
```
